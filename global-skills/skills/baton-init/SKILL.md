# Baton init

`.baton/` 폴더와 턴 종료 훅을 대상 프로젝트에 설치해서, 여러 세션에 걸치는 작업을 사용자가
매번 다시 설명하지 않아도 다음 세션이 이어받게 한다.

긴 작업은 여러 세션에 걸치는데 세션 사이에 모델은 기억을 유지하지 못하고, `resume` 목록은
쌓일수록 쓸모가 없어진다. 제목과 시각만으로는 무슨 작업이었는지 알 수 없기 때문이다.
`.baton/<slug>.md`는 모델이 직접 최신 상태로 유지하는 작은 마크다운 파일이고, 작업이 끝나도
지우지 않는다. 훅은 모델을 호출하지 않고 셸 명령으로 도는 덕분에 토큰을 쓰지 않으면서
"이 세션이 여기까지 관찰되었다"는 단서를 남긴다. 다만 사용자가 중간에 끊거나 프로세스가
죽으면 훅 자체가 돌지 않으므로, 정본은 어느 경우에도 마크다운 파일이다.

`.baton/` 파일 규약은 도구에 매이지 않는다. 파일을 읽고 쓰는 에이전트라면 자기 진입 파일에
규칙을 적어두는 것만으로 그대로 쓸 수 있다. 도구에 매이는 부분은 훅 **등록**뿐이라서 여기에는
Claude Code 스니펫만 들어 있다. 다른 도구를 쓴다면 설정 형식을 추측하지 말고, 스크립트만
설치한 뒤 그 도구의 어떤 턴 종료 이벤트에 걸어야 하는지 사용자에게 안내하거나 훅을 건너뛴다.

## 절차

대상 프로젝트 루트에서 작업한다. 대화에서 대상이 정해지지 않았다면 현재 작업 폴더를 대상이라고
가정하지 말고 사용자에게 확인한다.

### 1. 이미 있는 것 확인

- `.baton/`이 이미 있으면 신규 설치가 아니라 보수로 다룬다. 기존 작업 파일은 덮어쓰지 않고
  빠진 조각(README, 훅, 포인터 줄)만 채운다.
- 이 프로젝트가 쓰는 진입 파일을 확인한다. `CLAUDE.md`와 `AGENTS.md`가 흔하고, 이미 있는 것을
  쓴다. 둘 다 있으면 둘 다 손보고, 둘 다 없으면 어느 쪽을 만들지 사용자에게 묻는다.
- 진입 파일에 Baton 포인터 줄이 이미 있으면 3단계를 건너뛴다.
- `.claude/settings.json`에 Baton 훅이 `Stop`과 `StopFailure` 양쪽에 이미 걸려 있으면 5단계를
  건너뛴다.
- 프로젝트에 체인지로그(`CHANGELOG.md`, `pjt-docs/CHANGELOG.md` 등)가 있는지 확인해 둔다.
  2단계에서 쓴다.

### 2. `.baton/README.md` 생성

`templates/baton-readme.md`를 읽어 `.baton/README.md`로 쓰되, `{{CHANGELOG_LINE}}` 자리표시자를
치환한다. 1단계에서 체인지로그를 찾았으면 그것을 가리키는 짧은 구절로 바꾸고(예: "체인지로그가
있으면 `pjt-docs/CHANGELOG.md`에 한 줄 남겨도 된다"), 없으면 빈 문자열로 바꾼다. 없는 관례를
지어내지 않는다.

주의할 점이 세 가지 있다.

1. 끝난 작업은 `status: passed`로 두고 **지우지 않는다.** 내용이 지식베이스로 복사된 뒤에도
   마찬가지인데, 그 복사는 추가이지 대체가 아니기 때문이다. 폴더가 커져서 세션 시작 때 훑기가
   부담스러워지면 `passed` 파일을 `.baton/done/`으로 옮기고, 삭제하지는 않는다.
2. 프론트매터 예시의 `branch`와 `assignee`는 git이 있을 때만 쓰는 필드다. git이 없는
   프로젝트라면 둘 다 뺀다. `assignee`는 여러 사람이 배턴을 함께 쓸 때만 남긴다.
3. "무엇을 적고 무엇을 안 적나" 절은 `local/` 하위 절까지 **그대로 남긴다.** 배턴 파일은
   커밋되므로 credential 값을 넣지 않고 어디에 있는지와 무엇이라 부르는지만 적는다는 규칙이
   핵심이다. 분량을 줄이려고 이 절을 쳐내면 규약 자체가 보안 부채로 바뀐다.

### 3. 진입 파일에 포인터 줄 추가

기존 내용 뒤에 덧붙인다. 그 파일의 제목과 목록 스타일에 맞춰 문구를 다듬되 내용은 유지한다.

```
- **IMPORTANT**: 세션 시작 시 `.baton/` 최상위의 `running`·`waiting` 배턴만 읽는다. 진행 중
  작업이 있으면 그 맥락에서 이어간다. `done/`과 지난 배턴은 지금 요청과 관련 있을 때만 찾아본다
  — 전부 읽으면 컨텍스트만 낭비한다. 운영 규칙은 그 폴더의 README.md.
- **IMPORTANT**: 프로젝트에 남는 작업(코드·설정 변경, 이 프로젝트의 문서 작업)은 한 턴에 끝나
  커밋까지 마쳤더라도 배턴 한 장을 만들거나 갱신하고, 끝나면 `status: passed`로 닫는다. 판단
  기준은 걸린 턴 수가 아니라 프로젝트에 남는 변경인지 여부다. 조사·질의응답이나 프로젝트와
  무관한 산출물에는 만들지 않는다.
```

읽는 범위와 만드는 기준을 둘 다 이 줄에 담고 `.baton/README.md`로 미루지 않는다. 진입 파일은
매 세션 로드되지만 폴더 README는 한 걸음 뒤에, 그것도 읽힐 때만 읽히기 때문이다. "`.baton/`을
읽어라"만 있는 포인터는 폴더 전체를 읽으라는 지시가 되고, 만드는 기준이 빠진 포인터는 배턴이
아예 안 생기게 만든다. 실제로 자주 나는 실수는 한 턴 만에 고치고 커밋까지 끝낸 작업을 "끝난
일"로 보고 배턴을 안 남기는 것이라서, 두 번째 줄에 그 경우를 명시한다. 이유를 함께 적는 것도
수정의 일부인데, 이유가 붙은 규칙이 맨 지시보다 오래 지켜지기 때문이다.

### 4. 훅 스크립트 설치

`templates/baton-stop-hook.mjs`를 `<프로젝트 루트>/scripts/baton-stop-hook.mjs`로 복사한다.
`scripts/` 폴더가 없으면 만든다. 프로젝트가 훅 스크립트를 다른 곳에 모아둔다면 그 위치에 두고
5단계의 경로를 맞춘다. 프로젝트별 값이 들어 있지 않아서 그대로 복사하면 되고, 실행 시점에
자기 `cwd` 위쪽 어딘가에 `.baton/`만 있으면 동작한다.

### 5. 턴 종료 이벤트 두 개에 훅 등록

`templates/settings-snippet.json`을 `.claude/settings.json`에 병합한다. 파일이 없으면 스니펫
내용으로 새로 만들고, 있으면 해당 이벤트 배열에 **덧붙인다.** 먼저 읽어서 `PreToolUse`나
`SessionStart` 같은 무관한 훅을 덮어쓰지 않도록 한다. 4단계에서 기본 위치를 쓰지 않았다면
스크립트 경로를 고친다.

`Stop` 하나만 걸지 않고 `StopFailure`까지 거는 이유는, 턴이 그냥 끝난 경우가 아니라 오류로
죽은 경우를 놓치기 때문이다. 단서가 정작 필요한 상황이 후자다.

스니펫의 `${CLAUDE_PROJECT_DIR}`는 도구가 알아서 확장하므로 그대로 둔다. 또 스니펫은
`"command": "node"`와 `args` 배열을 쓰는 exec 형식인데, 셸 형식으로 바꾸면 치환된 경로를 셸이
다시 파싱해서 경로에 공백이 있을 때 깨진다. 수정할 일이 있어도 이 형태는 유지한다.

### 6. 기기 로컬 레인을 git에서 제외

`.gitignore`에 아래 두 줄이 없으면 추가한다.

```
.baton/.session/
.baton/local/
```

`.session/`은 훅이 쓰는 런타임 정보를 담고, `local/`은 팀에 넘길 수 없는 기기 로컬 설정값과
개인 자료를 두는 자리다. 둘 다 git으로 관리할 대상이 아니고 기기 사이에서 병합되지도 않는다.
`.baton/local/`은 설치할 때 만들지 않는다. 처음 쓸 때 만들면 되고, 비어 있는 무시 폴더는
잡음만 남긴다.

### 7. 결과 보고

새로 만든 파일과 이미 있어서 손대지 않은 파일을 구분해서 알리고, 어떤 진입 파일을 썼는지와
훅을 걸었는지(건너뛰었다면 그 이유를) 밝힌다. 이 프로젝트에서 다른 에이전트도 쓴다면 `.baton/`
파일 규약은 그쪽에서도 그대로 동작하며, 그 에이전트의 진입 파일에 포인터 줄만 추가하면 된다.
다만 사이드카는 그 도구의 훅을 같은 스크립트에 걸어야 돌아간다.

실제 턴 밖에서 훅을 발동시킬 방법이 없으므로 스모크 테스트는 하지 않는다. 파일이 있는지와 훅
설정이 파싱되는지만 확인한다.

## 참고

`templates/` 폴더에 이 스킬이 쓰는 파일이 있다.

- `baton-readme.md`: `.baton/README.md` 내용이며, 자리표시자는 `{{CHANGELOG_LINE}}` 하나다.
- `baton-stop-hook.mjs`: `Stop`과 `StopFailure`가 공용으로 쓰는 훅 스크립트이며 자리표시자가 없다.
- `settings-snippet.json`: `.claude/settings.json`에 병합할 Claude Code 훅 설정이다.
